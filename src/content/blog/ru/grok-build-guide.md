Grok Build объединяет чтение кода, планирование, изменения и проверку в терминале. Разделяйте возможности клиента, модели вашей учётной записи и источник оплаты: подписка или API.

**Факты и цены проверены: 2026-10-15. Цены в долларах справочные, без применимых налогов. Сверяйтесь с официальными тарифами и счётом.** Покупка и переход разобраны в [руководстве по новой подписке Grok](../xai-grok-x-subscription-plan-guide/).

## 1. Что такое Grok Build

Согласно документации xAI, Grok Build - это coding-agent для терминала с тремя основными режимами:

- Интерактивная полноэкранная TUI с поддержкой мыши.
- Headless CLI-путь для скриптов и автоматизации (`grok -p ...`).
- ACP-режим для интеграции с внешними приложениями (`grok agent stdio`).

На практике это не просто чат-обертка над командами. Это единая цепочка исполнения, где совмещаются планирование, правки, файловые операции, tool-вызовы и параллельные subagent-процессы.

## 2. Действующие тарифы и доступ

Новые клиенты сравнивают The X Subscription: Free ограничен; Plus стоит $8, Premium $30, Super $100, Ultra $200 в месяц. Страница цен включает Grok Build в Plus. После входа проверьте модели и остаток ресурса: старые SuperGrok и X Premium+ больше не являются единственным условием покупки.

Premium, Super и Ultra включают 4x, 15x и 50x использования Plus, а не фиксированное число задач. Grok Bot начинается с Premium. Действующий тариф пока можно сохранить; не объединяйте аккаунты только ради пробы Build. Командам нужно проверить назначение мест и политики организации.

## 3. Быстрый onboarding (примерно 5 минут)

### 3.1 Установка

macOS / Linux / WSL:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

Windows (PowerShell):

```powershell
irm https://x.ai/cli/install.ps1 | iex
```

### 3.2 Первая аутентификация

```bash
grok
```

По умолчанию первый запуск открывает браузерную аутентификацию. В окружениях без браузера (например, remote host или контейнер) используйте API-ключ:

```bash
export XAI_API_KEY="xai-..."
grok
```

Если удалённая среда не открывает браузер, используйте код устройства как альтернативу, а не обязательный шаг после обычного входа.

```bash
grok login --device-auth
```

### 3.3 Старт внутри репозитория

```bash
cd your-project
grok inspect
grok
```

Полезные стартовые prompts для production-репозиториев:

- "Map this repository and identify boot paths."
- "Enter plan mode first, do not edit files yet."
- "List risks first, then propose edits."

### 3.4 Headless и автоматизация

```bash
grok -p "Explain this codebase"
grok -p "Review this diff" --output-format json
```

Для IDE-оркестрации или внутреннего tooling используйте ACP:

```bash
grok agent stdio
```

## 4. Поддерживает ли он CLI и GUI? Похож ли на codex.app?

Короткий ответ: **сейчас Grok Build в первую очередь CLI/TUI, а не отдельное desktop GUI-приложение**.

- CLI: да, это основной вход.
- Интерактивный интерфейс: да, но терминальный (полноэкранный TUI), а не desktop-окно.
- Сценарий в стиле codex.app: возможен через ACP-интеграцию в другой софт, но это не дефолтная форма продукта.

Если команда предпочитает визуальные workspace-инструменты, Grok Build лучше рассматривать как terminal-centric agent-платформу, а не как GUI-замену один-к-одному.

## 5. Какие платформы поддерживаются

По официальным Getting Started документам подтверждены такие окружения:

- `macOS`
- `Linux`
- `WSL`
- `Windows PowerShell`

На уровне семейства продуктов возможности Grok также охватывают:

- `Web`
- `iOS`
- `Android`
- `X`

Важное разграничение: сам Grok Build позиционируется как терминальный coding-agent, а не как мобильное chat-приложение.

## 6. Модели и настройка

### 6.1 Grok 4.7, Fast и старые модели

Текущий обзор Build представляет `grok-4.7`; в ценах API остаётся `grok-build-0.1`. Старый идентификатор не доказывает, что это единственная или стандартная модель клиента. `grok-build` в примере настроек — имя конфигурации, не обязательно такой же идентификатор API.

Grok 4.7 Fast использует ту же модель на более быстрой инфраструктуре. Он доступен только в Cursor и Build с оплатой через тариф продукта, не через публичный xAI API. Бесплатный уровень Build его не включает. Скорость может сопровождаться большим расходом ресурса.

### 6.2 Проверить аккаунт и загруженные настройки

Используйте `grok models` в shell и `/model <name>` в TUI. Пользовательские модели и модель по умолчанию задаются в `~/.grok/config.toml`. Проектный `.grok/config.toml` предназначен главным образом для MCP, Plugins и правил разрешений, а не всех личных настроек. `grok inspect` показывает загруженные источники.

## 7. Общий лимит, API и стоимость Fast

### 7.1 Расход по подписке

У каждого оплаченного места недельный запас для допустимого использования собственных моделей в поддерживаемых интерфейсах Grok и Cursor. Задачи расходуют его по-разному; множители не гарантируют сообщения, задачи программирования или видео в день. Наблюдайте `/usage` и панель аккаунта в обычную рабочую неделю.

Сторонние модели Cursor оплачиваются с первого обращения. Публичный Grok API тоже оплачивается отдельно, без расхода этого лимита. У собственного endpoint действуют правила его поставщика.

### 7.2 Текущие ставки API и Fast

Цены стандартного глобального endpoint для `grok-4.7`, в долларах за миллион токенов. При достижении порога длинного контекста соответствующая ставка применяется ко всем токенам запроса, а не только к превышению.

| Входной контекст | Ввод | Кэшированный ввод | Вывод |
| --- | --- | --- | --- |
| Менее 200k токенов | $2.00 | $0.50 | $6.00 |
| От 200k токенов | $4.00 | $1.00 | $12.00 |

Fast внутри Cursor/Build стоит вдвое дороже стандартных токенов при коротком контексте и в 1,5 раза при длинном, с оплатой через тариф продукта. Инструменты могут оплачиваться дополнительно: прежняя единая оценка $5 за тысячу вызовов любого инструмента неприменима. **Дата данных: 2026-10-15, только для справки. Региональные endpoint, модели, инструменты и правила расчёта меняют итоговую сумму.**

## 8. Команды на каждый день и длительные задачи

`/model <name>` переключает модель, `/plan [description]` включает Plan, `/view-plan` показывает план. `/usage` показывает расход, `/context` — контекст, `/compact` сжимает историю. `/new` и `/resume` начинают или восстанавливают сеанс; `/rewind` возвращает к предыдущему шагу разговора. `/skills`, `/plugins`, `/mcps` открывают вкладки расширений.

`/goal <objective>` подходит для долгой работы с проверяемым результатом. `/create-workflow` создаёт процесс, `/workflow <name>` запускает его, `/workflows` открывает панель выполнения. `/loop` повторяет инструкции, `/tasks` показывает фоновые задачи. Проверяйте разрешения, стоимость и локальную `/help`.

Ограничение редактирования Plan независимо от режима разрешений: до одобрения редактируется только файл плана. Bash и MCP по-прежнему следуют разрешениям, а shell способен писать файлы. Plan не является песочницей только для чтения.

## 9. Частые возможности Grok и где они полезны

### 9.1 Поиск актуальной информации в реальном времени (Web + X)

Один из явных дифференциаторов - совмещение realtime web-поиска и поиска по X в одном ответном потоке. Это особенно полезно в задачах, чувствительных ко времени.

### 9.2 Agentic coding workflow

Помимо ответов на вопросы по коду, Grok Build может выполнять сканирование репозитория, генерацию плана, изменения в коде и объяснение diff, если выданы нужные права.

### 9.3 Параллельные subagent-потоки

Для крупных задач работу можно делить на несколько параллельных веток исследования. Это помогает в сложной диагностике инцидентов и много-модульном анализе.

### 9.4 Экосистема skills, plugins и MCP

Grok Build умеет обнаруживать локальные правила и каталоги skills, а также расширяется через plugins и MCP-интеграции. Это упрощает миграцию с других agent-платформ.

### 9.5 Мультимодальные возможности в той же продуктовой линейке

В семейство Grok также входят функции генерации и понимания изображений/видео, что полезно для документации, демо и контентных workflows.

## 10. Как оценить внедрение

Проверьте аккаунт, модель и оплату, затем попробуйте ограниченную задачу. Прочтите правила проекта, проверьте план и diff, выполните тесты или build. Выбирайте тариф по измеренному расходу, а не по старому названию подписки.

Если нужна настольная GUI, протестируйте конкретную интеграцию. При готовом процессе сравнивайте результат, полную стоимость и трудозатраты перехода на одной задаче. Доступ к инструментам не заменяет приёмку результата.
